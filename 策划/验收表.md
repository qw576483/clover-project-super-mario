## 驱动环境（可复现）

- 工程：`client`
- CLI 一律**先 `cd` 进工程**再跑（skill P-1；否则 `unity status` 空表）
- **探针** = `已清理（一次性产物，随 .ai-tmp 删除）`（skill §1.8：临时文件只此一处、用完即删）：
  `unity command run_script --file 已清理（一次性产物） --entry Probe.<场景>`
  —— 入口是 `void` 且**立刻返回**（`run_script` 的传输层 30 秒超时，而一个场景要跑十几秒到几十秒），
  场景自己往**游戏日志**里写 `场景结束：<名字>` 当完成标记；探针清单见 `probe.cs` 里的 `public static void <X>() => Start("<scene>", ...)`
  （当前 24 个场景（本轮新增 **`physics` / `platformspawn`**）：`boot / menu / intro / crouch / goomba / pause / flag / gameover / level12 /
  coinroom / coinroom12 / reshoot / koopa / piranha / platform / survey / audit12 / walk12end /
  section12 / mouth2 / parsecheck / uidiag`）
- **驱动** = `已清理（一次性产物，随 .ai-tmp 删除）`（`-Scene a,b,c -SceneTimeout 150`，**每个场景一个新 Play 会话**）。
  ⚠️ 同目录的 `run.ps1` 是同一件事的早期版本（**一个 Play 会话里连跑多个场景**）—— 它会在场景结束于
  `Result` / `GameOver` / `Boot` 之后**拍出单色空帧**（见上面的状态段与 §1.13 第 5 条），**只作参考保留**。
- **按键注入必须走 `Game.AttachInput` 桩**（登记项 E-11）：本机编辑器窗口最小化 + 管理员权限，
  OS 级注入在引擎 Tick 相位读不到。除按键这一层外，跑的都是原代码
- 改代码后必须 **`refresh` → `recompile`**（顺序不能反，见 skill P-2）；
  改 `.txt` 关卡数据后必须 `unity command menu --path "Assets/Refresh"` 强制重导入，否则跑的是旧文本
